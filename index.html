Chapter 01Personal project · In progress

Terraform EKS Platform

A small EKS platform built entirely in Terraform, designed to be planned on every pull request and delivered by GitOps, and to be cheap enough to create for an afternoon and destroy afterwards.

  1. State

    Designed so every change starts from shared, locked state that outlives the platform: a versioned, encrypted S3 bucket with native locking.

  2. Network

    Private by default and cheap to run: subnets across availability zones, a single NAT gateway, and a free S3 endpoint so image pulls skip the NAT.

  3. Cluster

    An EKS control plane and a managed node group in private subnets, with the cluster API allow-listed to known addresses.

  4. Identity

    Cluster access goes through EKS access entries, not a shared kubeconfig, and the EBS CSI driver’s controller gets least-privilege AWS access through IRSA, with no long-lived keys.

  5. CI

    The pipeline is designed to authenticate with GitHub OIDC instead of stored keys, plan on every pull request, fail on high-severity Trivy findings, and apply only after approval.

  6. GitOps

    Flux runs inside the cluster and pulls from a separate GitOps repository, so no CI system needs cluster credentials.

Chapter 02In progress · Release candidate

PR Guardian Action

A GitHub Action that reviews infrastructure pull requests before a human has to. Rules decide; AI only advises.

PR Guardian is designed to read the diff of a pull request that touches Terraform, Kubernetes YAML, GitHub Actions workflows or Dockerfiles, and run the added lines through a small set of readable rules. Findings are meant to land as one review with inline comments, most severe first, with re-runs updating that review instead of piling on. Posting reviews and re-run updates are still being verified on live pull requests before release.

By design, an optional AI layer adds advice on what regex rules can’t see. It is labelled advisory and never reaches the pass/fail gate. The Action doesn’t check out your code, and with no API key it talks to nothing but GitHub.

04 — How I got here

I trained as an electrical and electronics engineer, and I still think about systems the way that discipline taught me: inputs, failure modes, and what happens under load.

I joined Incedo in August 2021 to work on CI/CD and cloud infrastructure, and I have stayed close to production for the five years since. Between 2021 and 2025 I led the migration of fifteen microservices to Amazon EKS and moved our repositories from Jenkins to GitHub Actions. In September 2025 I became DevOps Engineer, Platform Automation, at Incedo: EKS operations, access management and deployments.

Outside work I build in public with Terraform and GitHub Actions, to widen a toolkit that grew up on CloudFormation. I’m based in Chennai and looking for platform and DevOps roles in Bangalore.
